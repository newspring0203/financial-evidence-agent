# Financial Evidence Agent

**공시의 숫자를 조회하고, 답변의 근거를 추적하는 Financial AI Agent**

[웹 서비스](https://financial-evidence-agent.onrender.com/) · [실험 코드](LLM_test/) · [자동 테스트](tests/)

`Tool Calling` · `Hybrid Retrieval` · `Evidence-First RAG` · `MCP`

## 개발 배경과 목표

> 정답 문단을 찾아도, 모델은 다른 문단을 인용할 수 있었습니다.

재무 수치 조회·계산 함수를 LLM 도구로 연결하는 데서 시작했습니다. 실제 공시로 검색과 답변을 검증하면서 연결·별도 문맥의 혼합, 계산 도구 호출 누락, 검색된 정답과 다른 인용, 선택기의 잘못된 후보 ID를 발견했습니다.

이 문제를 단계별로 분리해 실험하고, **검색 → 근거 선택 → 검증 → 답변** 구조로 발전시켰습니다. 웹에서는 사용자가 공시에 질문하고, 선택된 근거 원문과 계산 과정을 함께 확인하도록 구성했습니다.

| 관찰 | 설계에 반영한 내용 |
| --- | --- |
| 재무 조회 후 계산 호출 누락 | 재시도 실험과 수치·구조화 출력 검증 |
| 연결·별도 주석의 검색 범위 혼합 | 문단 범위 감사와 파서 수정, 동일 조건 재평가 |
| 정답 검색 후 다른 근거 인용 | 근거 선택과 답변 생성 분리 |
| 선택기의 잘못된 후보 ID | 후보 ID `enum` 제한과 한 차례 재요청 |
| 인용은 맞지만 답변 표현이 부정확 | 서비스의 로컬 답변을 원문 문장 선택 방식으로 구성 |

## 모델 및 실행 환경

**반복 실험 단계에서는 로컬 Ollama와 소형 Qwen3를 선택했습니다.** OpenAI API 연결 과정에서 잔액 부족을 확인했고, 검색 전략과 프롬프트를 바꿔 가며 반복 평가할 수 있는 실행 환경이 필요했습니다. M1 Mac·RAM 16GB 환경에서 생성 모델과 임베딩 모델의 역할을 나누어 구성했습니다.

| 구분 | 사용 도구·모델 | 역할 |
| --- | --- | --- |
| 모델 실행 환경 | Ollama | 로컬 추론과 임베딩 API 제공 |
| 생성·선택 모델 | `qwen3:1.7b` | 도구 호출 실험, 근거 선택과 답변 생성 |
| 검색용 임베딩 | `qwen3-embedding:4b` | 질문·공시 문단의 벡터화와 Dense 검색 |
| 비교용 임베딩 | `qwen3-embedding:0.6b` | 임베딩 규모에 따른 검색 결과 비교 |

로컬 실행으로 외부 API 호출료 없이 실험을 반복했습니다. 이 선택으로 소형 모델의 도구 호출 누락과 구조화 출력 오류를 직접 관찰하고, 모델·프롬프트·검색·검증 단계별로 개선을 시도할 수 있었습니다. 실행에는 로컬 메모리와 추론 시간이 필요하며, 서비스용 모델 선택은 답변 품질·지연 시간·운영 비용을 함께 평가하는 후속 과제로 두었습니다.

개발 과정에는 Codex를 코드 작성·디버깅·실험 자동화에 활용했습니다. 시스템의 실제 추론은 Python 코드가 Ollama의 Qwen3 모델을 호출하는 경로로 실행했습니다.

## 실험 결과와 분석

**검색 성능과 최종 답변 품질을 단계별로 측정했습니다.**

- **검색:** 개발 질문 14개에서 BM25 Hit@3 **0.7857** → 명시적 연결 범위 Hybrid **1.0000**.
- **병목:** 추가 개발 질문 12개에서는 정답 검색 **12/12**에도 답변 생성 **6/12**. 근거 선택 단계의 실패를 별도로 분석했습니다.
- **검증:** 자동 테스트 **73개**, 공개 고정 입력의 SHA-256 확인, MCP 클라이언트의 네 도구 호출을 검증했습니다.

검색·답변 수치는 각 실험의 개발 질문에 대한 결과입니다. 답변 생성 비율과 의미적 정확성을 구분하며, 세부 조건과 비교 결과는 아래에 정리했습니다.

## 설계 결정과 서비스 반영

**재무 공시 답변에서는 원문 추적성과 검증 가능한 출력 구조를 우선했습니다.**

검색 실험에서 명시적 연결 범위 Hybrid 설정의 높은 정답 포함률을 확인했지만, 후속 생성에서는 선택기 오류와 부정확한 답변 표현이 남았습니다. 이를 바탕으로 검색·근거 선택·답변 생성을 분리하고 각 단계의 결과를 검증하도록 설계했습니다.

서비스의 로컬 경로에는 후보 ID 제한과 한 차례 재시도를 적용하고, 선택한 근거에서 원문 문장을 골라 답변하도록 구성했습니다. 사용자는 답변 문장과 출처를 바로 대조할 수 있습니다. 원문 발췌 방식은 자유로운 요약·복합 질문에 대한 종합 설명 범위를 줄이는 선택이므로, 후속 평가에서는 근거 적절성과 함께 답변의 충분성도 확인할 계획입니다.

공개 웹은 공시 조회·계산·근거 확인을 제공하고, 로컬 모델 경로는 추론 환경이 준비된 경우에 활성화합니다. 실험에서 사용한 모델과 공개 배포에서 제공하는 실행 범위를 구분해 관리합니다.

## 답변 처리 구조

### LLM 도구 호출

OpenAI Responses API의 Function Calling과 JSON Schema를 사용합니다. 모델의 도구 선택 → 서버 실행 → 결과 반환 → 후속 호출 또는 최종 답변으로 이어지는 반복 구조입니다.

| 도구 | 역할 |
| --- | --- |
| `get_financials` | 기업·연도·연결 구분·지표에 맞는 공시 금액 조회 |
| `calculate_change` | 조회한 당기·전기 수치 ID로 증감률 계산 |
| `search_disclosures` | 공시 문단 검색 및 출처 반환 |
| `reconcile_prior` | 당기 보고서 비교금액과 전기 보고서 금액 대사 |

웹에서는 사용자가 연결한 기업·연도·재무제표 범위에 맞춰 실행합니다. 출처 ID와 추출 텍스트의 문자 위치·SHA-256을 연결하고, 발췌 구간과 계산 결과의 일치를 검증합니다. 의미 해석은 연결된 원문과 함께 확인할 수 있습니다.

### 로컬 LLM 근거 기반 답변

로컬 추론이 활성화된 환경에서는 BM25와 Dense 검색 결과를 RRF로 결합하고, 모델이 근거 후보를 선택합니다. 후보 ID를 JSON Schema의 `enum`으로 제한하고 잘못된 선택은 한 차례 재요청합니다. 선택한 문단에서 답변 문장을 고른 뒤 원문의 문장을 출처와 함께 표시합니다.

```text
질문 → 연결·별도 범위 확인 → BM25 + Dense 검색
     → 근거 후보 선택·검증 → 원문 문장 선택 → 답변과 출처 표시
```

이 경로는 공시 원문을 발췌하는 답변 방식입니다. OpenAI의 반복 도구 호출과 로컬의 근거 선택·문장 선택은 별도 경로로 구성했습니다. 공개 Render 서비스의 로컬 추론은 비활성 상태이며, 운영 환경의 기능 설정에 따라 사용 가능한 모드를 표시합니다. 사용자 문서는 서버 내 별도 검색 경로에서 처리합니다.

### MCP

웹과 MCP는 네 가지 도메인 함수를 공유합니다. 웹은 함수를 직접 호출하고 외부 MCP 클라이언트에는 `FastMCP` stdio 어댑터로 제공합니다. MCP SDK 클라이언트에서 초기화·도구 목록·네 도구 호출을 확인했습니다. MCP 데이터 조회에는 별도로 준비한 `data/dart.json` 스냅샷이 필요합니다.

## 실험과 개선 과정

| 실험 | 확인한 문제와 접근 |
| --- | --- |
| Exp 01–03 | 로컬 Qwen의 도구 선택, 계산 호출 누락 재시도, 구조화 출력·수치·근거 검증 |
| Exp 04–06 | 공시 RAG 답변 생성, 컨텍스트·스키마 조정, 검색 문단 수와 스키마 조건 비교 |
| Exp 07 | BM25·Dense·Hybrid 비교, Gold 라벨 검토, 연결/별도 범위 감사와 파서 수정 후 재평가 |
| Exp 08A–B | 검색 결과를 답변 생성에 연결하고 인용 오류 분석 |
| Exp 08C v1–v4 | 근거 선택과 생성을 분리하고 출력 구조·인용 연결 개선 |
| Exp 08D | 고정 후보를 활용한 선택기·직접성·의미적 지지 진단과 회귀 평가 |

검색 성공, 근거 선택 성공, 답변 정확성을 서로 다른 평가 항목으로 관리합니다. 정답 문단을 검색해도 선택기 출력 오류나 답변 표현 오류가 발생할 수 있어 각 단계의 실패를 구분합니다.

### 검색 비교

Exp 07F의 삼성전자 2024 공시 개발 질문 14개, Top-3 비교입니다.

| 검색 조건 | Hit@3 | MRR@3 |
| --- | ---: | ---: |
| BM25 | 0.7857 | 0.6667 |
| Dense · Qwen3 Embedding 4B | 0.8571 | 0.6905 |
| Hybrid · Qwen3 Embedding 4B | 0.8571 | 0.7143 |
| Hybrid · 명시적 연결 범위 · Qwen3 Embedding 4B | 1.0000 | 0.9167 |

Hit@3는 상위 세 문단에 Gold 근거가 포함된 질문 비율이며, MRR@3는 첫 정답 문단의 순위를 반영합니다. 파서 수정으로 별도 문맥 11개를 재분류해 후보가 701개에서 690개로 바뀌었습니다. 범위 정확성을 확인한 결과와 검색 점수의 변화를 구분해 해석합니다.

### 검색과 답변의 차이

Exp 08C v4의 추가 개발 질문 12개를 두 조건으로 비교했습니다. 생성 모델은 `qwen3:1.7b`, 임베딩은 `qwen3-embedding:4b`, temperature 0, seed 42입니다.

| 조건 | 검색 성공 | 답변 생성 | Gold 인용 |
| --- | ---: | ---: | ---: |
| Unknown 범위 허용 | 11/12 | 10/12 | 10/12 |
| 명시적 연결 범위 | 12/12 | 6/12 | 5/12 |

답변 생성은 응답을 산출한 비율이며, Gold 인용은 지정 근거와의 일치 지표입니다. 답변의 의미적 정확성은 별도로 검토합니다. 이 질문들은 앞선 검색 평가에도 사용한 개발 데이터로, 두 조건의 후보 구성과 선택 정책을 함께 고려해야 합니다. Exp 08D는 해당 사례를 활용한 회귀 실험입니다.

## 검증과 재현 범위

| 항목 | 확인 범위 |
| --- | --- |
| 자동 테스트 | 73개 통과. 도구·오류 처리·세션 격리·문서 검색·재고 평가·로컬 답변 경로·공개 입력 무결성 |
| 웹 JavaScript | 구문 검사 통과 |
| 로컬 모델 | Qwen 기반 실험 및 웹 API의 근거 선택·원문 문장 답변 흐름 확인 |
| OpenAI | 도구 호출 루프와 모의 응답 검증 완료. 실제 API 성공 흐름은 잔액 확보 후 확인 예정 |
| MCP | SDK 클라이언트로 초기화·목록·네 도구 호출 확인 |

저장소에는 실험 코드, 실험 의존성, 질문·Gold 라벨, Exp 08D의 고정 입력과 SHA-256 manifest를 포함합니다. Exp 08D는 원래 로컬 실행 폴더가 있으면 해당 입력을 사용하고, 그 폴더가 없는 환경에서는 공개 고정 입력을 사용합니다. 메타데이터의 프로젝트 절대 경로를 정리했으며 원본 파일 해시와 공개 파일 해시를 함께 기록했습니다.

전체 공시 코퍼스·임베딩 캐시·초기 실험 출력은 로컬에서 관리합니다. Exp 07F처럼 과거 캐시와 해시를 비교하는 실험은 해당 원본 자료를 별도로 준비해야 합니다. 공개 고정 입력은 선택기 회귀와 근거 진단을 재현하는 범위입니다. Ollama 서버와 모델 가중치는 실행 환경에서 준비합니다.

## 자료 관리

- OpenDART 키는 공시 수집 요청에 사용합니다.
- 수집한 공개 공시·선택적으로 입력한 OpenAI 키·등록 문서는 서버 메모리 세션에서 관리합니다.
- 세션은 최대 1시간 후 만료되며 로그아웃·서버 재시작 시에도 정리됩니다.
- 등록 문서는 서버 내부 검색에 사용하고 외부 LLM 전송 경로와 분리합니다.
- 문서 형식은 UTF-8 TXT·Markdown, 파일당 최대 1MB, 세션당 최대 30개입니다.
- 재고 평가는 기존 평가손실이 없는 품목별 기말 평가를 대상으로 계산 근거를 표시합니다.
