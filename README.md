# Financial Evidence Agent

**실제 공시에서 재무 수치를 조회하고, 계산 결과를 원문 근거와 연결하는 재무 검토 보조 서비스입니다.**

[웹 서비스](https://financial-evidence-agent.onrender.com/) · [GitHub](https://github.com/newspring0203/financial-evidence-agent)

공시의 수치와 설명을 확인하는 과정에서 어떤 도구를 실행했고, 어떤 자료를 근거로 사용했는지 함께 보여줍니다. OpenDART 조회·계산·검색 함수를 LLM이 호출할 수 있도록 연결했으며, API 키 없이 사용할 수 있는 문서 작업 공간과 재고자산 평가 기능도 제공합니다.

## 주요 기능

| 기능              | 제공 내용                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| Disclosure Review | 선택한 기업의 당기·전기 사업보고서를 조회하고 매출·영업이익·재고자산의 수치와 증감률을 확인합니다.       |
| 공시 근거 검색    | 관련 문단, 보고서 제목, 주석 제목, DART 원문 링크와 추출 텍스트 위치를 제공합니다.                       |
| 전기 금액 대사    | 당기 보고서의 전기 비교금액과 전기 보고서의 당기금액을 비교합니다. 차이가 있는 항목은 추가 검토 대상으로 표시합니다. |
| RFI 초안          | 분석에서 조회한 계정에 대해 추가로 요청할 자료·확인 목적·질문과 다운로드 가능한 초안을 제공합니다.       |
| PBC Workspace     | UTF-8 TXT·Markdown 자료를 계정 폴더별로 등록하고 해당 폴더 안에서 검색합니다.                            |
| 재고자산 평가     | 품목별 원가와 순실현가능가치를 비교해 평가 후 장부금액·평가손실과 산출 과정을 표시합니다.                |
| Reference Desk    | 회계기준·공시·경제통계 등 외부 공식 자료 사이트로 이동합니다.                                            |

## 사용 흐름

1. 본인의 OpenDART API 키와 회사명 또는 DART 고유번호를 입력합니다.
2. 사업연도와 연결·별도 구분을 선택해 공시를 연결합니다.
3. 질문을 입력하고 기본 분석 또는 LLM 도구 호출을 실행합니다.
4. 검토 내용, 근거 원문, 도구 실행 기록을 함께 확인합니다.
5. 필요한 경우 검토 메모를 내려받거나 추가 자료 요청 초안을 작성합니다.

예시 질문:

- 매출과 재고자산의 전기 대비 증감률을 비교하고 재고 평가정책 주석을 찾아줘.
- 재고자산 평가정책과 평가손실 관련 주석을 찾아줘.
- 특수관계자 거래 관련 공시 근거를 찾아줘.

기본 분석은 지원하는 질문 유형에 맞춘 조회·계산 흐름입니다.

| 항목 | 핵심 구현 | 검증 상태 |
| --- | --- | --- |
| Tool Calling | 함수 호출·결과 반환 루프와 구조화 출력 | 모의 응답 기반 프로토콜·오류 처리 검증 |
| Retrieval | BM25·문단 구조 기반 공시 검색과 근거 추적 | 실제 공시로 검색 순위·정답 문구 포함 여부 비교 |
| MCP | 공유 도메인 도구 4개의 stdio 어댑터 | MCP SDK 클라이언트에서 네 도구 실제 호출 확인 |
| Evaluation | 로컬 테스트·검색 비교·LLM 평가용 코드 | 자동 테스트 61개 통과, 실제 LLM 전체 흐름은 검증 예정 |

### LLM 도구 호출 구조

OpenAI Responses API의 Function Calling과 JSON Schema 기반 구조화 출력을 사용합니다. LLM이 도구를 선택하면 서버가 실행 결과를 반환하고, 모델이 후속 호출 또는 최종 답변을 생성하는 반복 구조입니다.

| 도구                 | 역할                                                |
| -------------------- | --------------------------------------------------- |
| `get_financials`     | 기업·연도·연결구분·지표에 맞는 공시 금액 조회       |
| `calculate_change`   | 조회한 당기·전기 수치를 이용한 증감률 계산          |
| `search_disclosures` | 공시 문단 검색과 출처 정보 반환                     |
| `reconcile_prior`    | 당기 보고서의 전기 비교금액과 전기 보고서 금액 대사 |

웹 실행에서는 선택한 기업·연도·연결구분을 벗어나는 호출을 제한합니다. 계산 도구는 먼저 조회한 수치 ID를 사용해야 하며, 최종 주장에 조회하지 않은 출처 ID가 붙으면 해당 주장을 제외합니다.

### 공시 검색과 근거 검증

공시 검색은 BM25, 한국어 문자 2-gram, 검색어 확장과 주석 제목 경계를 활용합니다. 확인 가능한 연결·별도 주석 문맥으로 범위를 제한하고, 겹치는 발췌 구간을 줄입니다. 제목이나 문맥이 식별되지 않는 구간은 원문 확인이 필요합니다.

검색된 공시를 LLM 답변의 컨텍스트로 제공하는 검색 증강 구조입니다. 공시 검색에는 키워드·통계 기반의 BM25를 적용했으며, 임베딩 기반 하이브리드 검색으로 확장할 계획입니다. 등록한 사용자 문서는 별도의 서버 내 검색 경로에서 처리합니다.

각 근거에 출처 ID, 추출 텍스트 내 문자 위치, SHA-256 해시를 연결해 원문을 추적할 수 있습니다. 출처와 발췌 구간의 일치 여부 및 계산 결과를 자동으로 검증하며, 답변의 해석과 근거의 적절성은 연결된 원문과 함께 검토할 수 있습니다.

### MCP 어댑터

웹과 MCP는 동일한 네 가지 도메인 함수를 공유합니다. 웹은 해당 함수를 직접 호출하고, 외부 MCP 클라이언트에는 `FastMCP`의 stdio 어댑터로 제공합니다.

MCP는 별도로 준비한 `data/dart.json` 공시 스냅샷을 사용합니다. 실제 MCP SDK 클라이언트를 연결해 초기화, 도구 목록 조회, 네 도구 호출과 잘못된 범위의 요청 거부를 확인했습니다. 웹의 BYOK 조회는 사용자 키로 공시를 수집해 메모리에서 처리합니다.

### 검색 비교 결과

삼성전자·SK하이닉스의 실제 공시 스냅샷에서 개발 질문 8개와 추가 검증 질문 8개를 사용했습니다. 각 질문의 정답 문구를 지정하고, 동일 데이터·질문으로 검색 방식을 비교했습니다.

| 검색 방식        | 개발 질문 Hit@3 | 추가 검증 질문 Hit@3 | 추가 검증 MRR@3 |
| ---------------- | --------------: | -------------------: | --------------: |
| 기본 키워드      |             4/8 |                  6/8 |          0.5417 |
| 검색어 확장      |             4/8 |                  3/8 |          0.3125 |
| BM25 + 문단 구조 |             6/8 |                  8/8 |          0.8125 |

Hit@3는 상위 세 문단 중 지정한 정답 문구를 포함하는 결과가 있는 질문의 비율입니다. MRR@3는 첫 정답 문단의 순위를 반영합니다. 설명형 질문의 숫자 표 우선 문제와 반품 조건의 중요도를 보완한 뒤 추가 검증 질문의 MRR@3는 0.7917에서 0.8125로 바뀌었습니다. 개발 질문의 정답 포함률은 6/8로 유지되었습니다.

두 질문 세트 모두 결과를 확인하며 개선에 활용한 소규모 평가입니다. 다음 검증에서는 기업·기간·질문을 확대하고, 개선에 사용하지 않은 평가 세트를 별도로 구성할 계획입니다.

## 재고자산 평가 예시

모든 금액은 원, 가격과 비용은 단위당 금액입니다. 아래는 실제 기업 자료가 아닌 테스트용 입력입니다.

| 입력          | 제품 A | 제품 B |
| ------------- | -----: | -----: |
| 수량          |    100 |     50 |
| 단위원가      | 10,000 | 20,000 |
| 판매가격      |  9,500 | 25,000 |
| 추가 완성원가 |    500 |  1,000 |
| 판매원가      |    300 |    500 |

```text
단위당 순실현가능가치 = 판매가격 − 추가 완성원가 − 판매원가
단위당 평가금액 = min(단위원가, 단위당 순실현가능가치)
평가 후 장부금액 = 단위당 평가금액 × 수량
평가손실 = 단위원가 × 수량 − 평가 후 장부금액
```

예상 합계는 평가 전 원가 2,000,000원, 평가 후 장부금액 1,870,000원, 평가손실 130,000원입니다. 품목별 평가 후 합산하므로 다른 품목의 가치 상승으로 손실을 상계하지 않습니다.

현재 계산 범위는 기존 평가손실이 없는 재고의 품목별 기말 평가입니다. 환입·품목군 평가·원재료의 특수한 평가 상황·세금 효과는 처리하지 않습니다. 음수 순실현가능가치는 별도 검토 대상으로 안내합니다. 입력 가격·원가의 타당성을 자동 판단하거나 영업이익 영향을 추정하지 않습니다.

기준 참고: K-IFRS 제1002호 재고자산 — [한국회계기준원 시행 중 기준서 목록](https://www.kasb.or.kr/front/board/ingAccountingList.do). 국제기준 참고: [IFRS Foundation · IAS 2 Inventories](https://www.ifrs.org/issued-standards/list-of-standards/ias-2-inventories/).

## 자료와 세션

- OpenDART 키는 공시 수집 요청에 사용하며 세션에 보관하지 않습니다.
- 수집한 공개 공시, 선택적으로 입력한 OpenAI 키, 등록 문서는 서버 메모리 세션에서 관리합니다.
- 세션은 최대 1시간 후 만료되며 로그아웃·서버 재시작 시에도 정리됩니다.
- 등록 문서는 외부 LLM으로 전송하거나 애플리케이션에서 디스크에 저장하지 않습니다.
- 등록 형식은 UTF-8 TXT·Markdown, 파일당 최대 1MB, 세션당 최대 30개입니다.
- 폴더 코드는 사용자 작업 분류입니다.
